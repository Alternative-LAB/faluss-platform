# Bloc contextuel Me — preuve locale

`v3-composition-regression.php` utilise une base Link en mémoire. Il vérifie les quatre catégories, les cinq fournisseurs, la normalisation des URL, le refus d'URL hostiles et d'image étrangère, la limite d'un bloc par catégorie, la prévisualisation sans écriture, le conflit de version 409 sans écriture, la conservation des blocs lors d'un changement de catégorie, l'activation, le masquage, la suppression explicite et la parité de projection entre aperçu et carte publique.

`v3-contextual-browser.js` utilise les vues PHP réelles du Studio mais des réponses HTTP simulées. Chromium et WebKit ont passé les largeurs 390, 768, 1024 et 1440 px. Le test contrôle l'éditeur mobile et web, la sélection au toucher ou à la souris depuis la carte web, le brouillon visible avant sauvegarde, la requête de sauvegarde unique, le rechargement simulé, le lien public permanent, le lecteur YouTube chargé au clic et le repli Twitch quand la carte est trop étroite. Les trois captures sont issues de Chromium ; l'avatar et la couverture y apparaissent sans image car les pièces jointes du fixture ne sont pas servies. Le titre du brouillon est injecté dans le HTML du fixture et ne démontre pas une écriture WordPress.

Le rendu sur WordPress/MariaDB isolé avec écritures API réelles, le modèle Elementor cible et les appareils physiques restent à vérifier avant intégration et publication. Ces captures ne prouvent pas que le code est installé sur faluss.me. Le moteur Docker local était indisponible lors de cette passe ; il faut refaire son diagnostic avant la recette isolée.
